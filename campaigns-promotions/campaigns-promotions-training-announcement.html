🧰 Campaigns & Promotions – Key Concepts

In SFCC, a Promotion defines the discount logic (percentage off, fixed price, free gift, shipping discount, etc.), while a Campaign is the container that schedules when and to whom that promotion applies.

A promotion only goes live once it is attached to an active campaign with a valid start/end date — a common source of confusion when a promotion "doesn't seem to work."

🔎 Real Life Example

A "Free gift with purchase" promotion was launched for a campaign, alongside an existing "-20% sitewide" promotion.

Because promotion compatibility and ranking were not properly configured:

  • Both promotions applied together unintentionally
  • Some customers received a discount far beyond what was planned
  • The issue was only caught after several orders had shipped

👉 Result: unplanned margin loss and manual order corrections.

⚠️ Key Risks

  • Overlapping promotions applying together unintentionally
  • Campaigns left active after the intended end date
  • Coupons or qualifiers misconfigured, granting unintended eligibility
  • Untested promotions going live directly in production
  • Emergency replication requests, with all the potential impacts this can generate

📊 Did you know?
Promotion ranking and compatibility rules determine which promotions can combine — without them, SFCC applies its own default logic, which may not match business intent.

🧠 Best Practices

  • Always test promotions in a sandbox/staging environment before go-live
  • Define promotion compatibility and ranking explicitly
  • Set clear start and end dates on every campaign
  • Review active campaigns regularly and archive expired ones
  • Use quotas to control coupon usage and prevent abuse
  • Use clear, consistent naming conventions for promotions and campaigns

🔧 Tip: Debugging a Complex Promotion

When a promotion isn't applying as expected, it's not always easy to pinpoint which condition is causing the issue — especially with multiple customer groups, exclusions, and product restrictions combined.

Start simple, then add complexity step by step:

  1. Create the simplest version of the promotion (e.g. 30% off for everyone) and test it
  2. Add one condition (e.g. a customer group) and test again
  3. Add the next condition (e.g. an exclusion) and test again
  4. Repeat for each remaining condition — one at a time

If the promotion stops working right after adding a condition, that condition is where the issue lies. This isn't a formal SFCC rule — just a practical troubleshooting method that saves time on complex promotions.
